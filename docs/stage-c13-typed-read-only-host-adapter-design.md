# Stage C13 typed read-only real-host adapter rehearsal — design

Date: 2026-08-05  
Branch: `feature/alarm-engine`

## Purpose

Stage C13 is the first bridge from the Stage C10 typed adapter contract and the Stage C11/C12 policy model back to the real Raspberry Pi.

It implements only six fixed real-host observation operations:

```text
inspect-host-contract
inspect-production-lock
capture-service-state
capture-mixer-state
capture-loopback-state
capture-dac-state
```

The remaining 27 `AdapterOperation` values remain inherited from `BlockedProductionAdapter` and must raise `ProductionAdapterBlocked` with their exact operation identity.

Stage C13 does not implement, expose or rehearse a production writer.

## Roadmap position

```text
Stages A, A2, B   physical split-bus DSP, ALSA and real-DAC proof
Stage C0          physical alarm-safe direct-failback proof
Stages C1-C7      package, snapshot and root-owned rollback foundations
Stages C8-C9      one transaction authority and stronger evidence replay
Stage C10         immutable typed host-operation contract; all operations blocked
Stage C11         immutable install, rollback, failback and uninstall programs
Stage C12         complete in-memory policy and failure simulation
Stage C13         typed read-only observations from the real host
```

No persistent Stage C installation or activation is approved by reaching Stage C13.

## Observation identity

The production protocol requires transaction-bound state captures. Stage C13 must not acquire the production lock or create an authoritative production transaction.

The adapter therefore generates a fresh in-memory identity with the form:

```text
stage-c13-observation-<random token>
```

This identity:

- is generated by the adapter, not supplied by the caller;
- is valid only for the four typed state-capture methods in that adapter instance;
- is explicitly non-authoritative;
- creates no directory or marker;
- cannot be used to call any inherited transactional operation;
- is discarded when the rehearsal process exits.

A substituted identity must return a typed `FAIL` result without touching the host.

## Fixed observation boundary

The adapter accepts no path, service, mixer, device or command override.

It is pinned to:

```text
Architecture: aarch64
Current ALSA route: /etc/alsa/conf.d/99-a-clockwork-plex-shared.conf
Current route SHA-256: 08d000933e132af4fe0d66f1f80fd6ba08d15398b98f5ea986f69709139e74b9
Production lock: /run/lock/a-clockwork-plex-audio-route.lock
ALSA card alias: Pro
Loopback: snd_aloop index=7 id=ACP_Loopback pcm_substreams=2 pcm_notify=1
DAC: S16_LE, stereo, 44100 Hz, period 1024, buffer 8192
```

The exact service boundary is the six `ServiceUnit` enum values from Stage C10.

The exact physical ALSA controls are mapped to the four logical Stage C10 mixer fields:

| Physical ALSA control | Typed field |
|---|---|
| `A Clockwork Plexamp` | `plexamp_output` |
| `A Clockwork AirPlay` | `airplay_output` |
| `A Clockwork Master` | `music_master` |
| `A Clockwork Alarm` | `maximum_alarm_volume` |

## Allowed host access

The real-host source may perform only these fixed read operations:

```text
lstat/read_text on fixed files and proc/sysfs paths
systemctl show <fixed-unit> --property=LoadState --value
systemctl is-active <fixed-unit>
systemctl is-enabled <fixed-unit>
amixer -c Pro sget <fixed-control>
fuser <resolved Pro card playback device>
read-only /proc process evidence for returned DAC-owner PIDs
```

The production-lock path may be inspected with `lstat`; it must never be opened or created.

The ALSA `Pro` alias is resolved read-only to determine the current numeric card for `/dev/snd/pcmC<n>D0p`. The numeric card is not accepted from the caller.

## Explicitly forbidden

Stage C13 has no path for:

```text
flock or production-lock acquisition
production transaction creation
filesystem snapshot or managed-file copy
service start, stop, restart, enable or disable
systemd daemon-reload
amixer sset/cset or any mixer write
modprobe or module mutation
PCM or DAC open
aplay or finite audio probe
CamillaDSP execution or signalling
route selection
installation, activation, failback, rollback or uninstall
approval marker creation or consumption
```

There is no generic command runner, raw `argv`, caller-supplied command, callback dispatch table or dynamic method-name execution.

## Rehearsal wrapper

The wrapper is prepare-only by default.

Prepare-only:

- invokes no sudo;
- creates no evidence directory;
- performs no host observation;
- prints the exact guarded command.

The guarded mode requires:

```text
--observe-read-only
--confirm STAGE-C13-TYPED-READ-ONLY-HOST-ADAPTER
```

It uses one constrained sudo command and a fresh directory directly beneath `/var/tmp`:

```text
/var/tmp/a-clockwork-plex-stage-c13-read-only-adapter.<suffix>
```

Root may write only inside that evidence directory. The directory is returned to the invoking user after capture.

## Acceptance checks

The guarded rehearsal must emit these checks in this exact order:

1. `root-scope`
2. `observation-identity`
3. `protocol-conformance`
4. `host-contract`
5. `production-lock-boundary`
6. `service-snapshot`
7. `mixer-snapshot`
8. `loopback-snapshot`
9. `dac-snapshot`
10. `blocked-operation-boundary`
11. `evidence-integrity`
12. `activation-interface`

Acceptance requires:

- all twelve checks are `PASS`;
- the real production-lock path remains absent and unopened;
- the three application services are loaded, active and enabled;
- the three future Stage C services are not found;
- all four mixer fields are present and valid percentages;
- the exact loopback contract is loaded;
- the exact DAC format is observed;
- structured DAC-owner evidence is present for the current Node/Plexamp owner;
- exactly six operations return typed real-host observations;
- exactly 27 operations refuse with `ProductionAdapterBlocked`;
- no production path is written;
- no activation interface exists.

## Evidence

A successful run writes only beneath its fresh evidence root:

```text
results.tsv
identity.tsv
typed-observations.json
blocked-operations.tsv
evidence-manifest.tsv
report.txt
```

The typed observation JSON is evidence only. It is not an activation snapshot and must never be reused as one.

## What Stage C13 does not prove

Stage C13 does not prove:

- production-lock acquisition or contention;
- authoritative transaction creation;
- exact activation-time filesystem backup;
- package validation or installation;
- service or mixer mutation;
- split-bus startup;
- runtime failback execution;
- exact rollback or uninstall;
- reboot persistence.

Those remain later, separately guarded roadmap stages. Persistent Stage C activation remains blocked.
